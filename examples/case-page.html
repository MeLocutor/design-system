O briefing vs. o problema real

O que pediram

"Ajustar o formulário que está longo demais." — briefing operacional focado em quantidade de campos.

O que estava quebrado de fato

Mapeei o fluxo completo e cronometrei cada etapa. O problema não era quantidade de campos, mas a ordem e a lógica da jornada: etapas redundantes, informações fora de sequência, formulário monolítico que travava o usuário.

O reframing que mudou a direção

Pergunta feita: "Onde o usuário realmente trava?" — não "quantos campos tem?".

Decisão: Reconstruí o percurso inteiro: removi etapas redundantes, reorganizei a sequência de informações, transformei formulário monolítico em etapas com progressão clara.

Decisões-chave

Automação via CPF

Pré-preenchimento de dados cadastrais via API de CPF reduziu digitação manual em ~60%.

Trade-off: dependência de API externa; mitigado com fallback manual.

Micro-vitórias (Progressive Disclosure)

Divisão em etapas com feedback visual de progresso manteve motivação; cada passo = conquista visível.

Trade-off: mais cliques totais, mas menor carga cognitiva por etapa.

KYC Postergado

Validação de identidade movida para depois do primeiro depósito (FTD), não no cadastro.

Trade-off: risco regulatório gerenciado com compliance; ganho massivo em conversão inicial.

Baseline em Vídeo

Gravação do fluxo original (10min) antes de qualquer mudança — auditoria e reprodutibilidade.

Trade-off: tempo extra upfront; elimina "achismo" e permite defesa da decisão com evidência.

Para recrutador técnico de startup B2B SaaS: o dado relevante não é a redução em si — é o método. Baseline gravado, decisões documentadas com rationale, resultado final reproduzível. Não foi "design bonito que reduziu tempo" — foi decisão de produto mensurável, com evidência.

Reflexão

O que aprendi: briefing "ajustar formulário" quase sempre esconde problema de jornada. A métrica de tempo é proxy de atrito — mas só vale se medida antes e depois com o mesmo método.

O que faria diferente: testaria a etapa de KYC postergado com usuários reais antes do lançamento (fizemos só validação interna). Também adicionaria telemetria de drop-off por campo, não só por etapa.
